Document structure

What each chapter of this guide covers, and where the structural sketches in the text sit.

 1. Background

the problem docorder solves, a minimal two-step job, the design trade-offs docorder makes, and the capability boundaries of the current version.

 2. Core concepts and terms

entity, upstream snapshot, operator and operator home, function, job and node, epoch and stage, runner and expected names. For each concept it says what it is, who creates it, and where it is stored.

 3. How a run works

what happens from the moment a run checks the job graph until each node has run, step by step. It also covers parallel execution, failure and retry, the special handling of a source node, and how docorder decides the fate of each result when it runs again.

 4. Fingerprints and hashes

the three kinds of hash in docorder, how to declare a dependency on external files with `fingerprint`, what `record` and `depend` are for, how to write a path template, and how to trace an entity that is redone on every run.

 5. Use cases

what kind of task each of several typical job graphs suits, and which tasks do not suit docorder.

 6. Configuration

how docorder finds the operators, what every key in `props.json` means, the arguments of a job and of a node, the arguments of the run function `execute`, which configuration the transform code and the template each read, and the environment variables involved.

 7. Operator types and the built-in functions

what separates the five operator types, which of docorder's own functions each type can use, and for each function which configuration keys it has, what it produces, and when it fails.

 8. Rendering functions and template variables

every variable a template can use directly, and the six ways to add a template variable when the built-in ones are not enough.

 9. Writing your own function

which base class to inherit, which methods to implement, which objects are available inside those methods, the conventions you must follow, where the code file goes, and how to write tests for it.

 10. Using docorder in your own project

the complete steps from installing, planning the directories, preparing the input data, and writing the operators and the start script, to running it, looking at the result, and running it again after a change.

 11. A data governance case study

the real jobs under `examples/data-governance/`, from the metric list of a dbt model to the root catalogue, the assignment table and the member tables, and how the four jobs hand their results to each other.

 12. Best practices

the conventions that keep docorder reliable, covering directories and naming, incremental runs and idempotence, how to organize operator homes, error handling, the cost of model calls, recovering from failures, and the common anti-patterns.

 Appendix A: The built-in functions

Every built-in function in one table: which operator type it implements, what it takes, and what it writes.

 Appendix B: Implementation index

Where each part of docorder lives: the modules, the base classes, and the helpers they rely on.

 Appendix C: Related documents

The README, the glossary, the contributing guide, and the other documents that go with this guide.
