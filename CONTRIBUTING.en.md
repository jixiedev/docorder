# Contributing

[中文](CONTRIBUTING.md)

## Environment

Python 3.10 or newer and [uv](https://docs.astral.sh/uv/) are required. Install a `jsonnet` executable when you use `JsonnetToPrompt`.

```bash
uv sync --group dev
uv run ruff check
uv run pytest
```

`tests/test_contract.py` holds the contract tests for scheduling behaviour. When you change how entities, the comparison, clearing, retry, or sources behave, add a case there first. `make quality` and CI also run the example job under `examples/data-governance/documentation/`.

## Where to change things

The runtime is in `src/docorder/`. `core/` holds entities, jobs, operators, and stage scheduling. `functions/` holds the source, map, reduce, fanout, and apply base classes. Built-in implementations are in `functions/impl/`. `utils/` holds errors, module loading, home search, and retry.

Operator homes live in directories listed by `DOCORDER_HOMES`. They are not installed with the package. The path separator is the same as for `PATH`, and a directory earlier in the list wins. Prefer an existing function for a new transform. When the existing types cannot express it, implement the function base class that matches `type` in `props.json`, put the class in the home's `primary.py`, and set `class` to `primary:ClassName`. The runner owns retry and the thread pool. Do not build another copy inside the function. Chapter 9 of [docs/guide.en.md](docs/guide.en.md) shows how.

## Changing the documents

The sources of the documents are the Markdown files in this repository. `docs/guide.md` is the only source of the guide. `README.md`, `glossary.md`, `CONTRIBUTING.md`, `SECURITY.md`, and `CHANGELOG.md` each become one page.

Regenerate the site after changing any Markdown:

```bash
uv run python scripts/build_figures.py
uv run python scripts/build_docs.py
```

The result lands in `docs/site/`, including the pages the guide is split into. Do not edit the generated pages by hand; change the source and run the script again. The body of the home page is a hand-written fragment under `scripts/templates/`, and the script wraps it in the same page shell as the other pages.

To add a chapter, add a second-level heading to both `docs/guide.md` and `docs/guide.en.md`. The two headings are paired by position, and the script builds one page per language from them. The per-chapter summaries live in the numbered list of the "Document structure" chapter, and the script reads them from there.

The diagrams in the guide are generated by `scripts/build_figures.py` and written straight into `docs/guide.md` and `docs/guide.en.md`. The script replaces each diagram in place between a pair of comments, so it can be run again and again:

```text
<!-- figure:slug:start -->
<!-- figure:slug:end -->
```

To change a diagram, change the matching function in `scripts/build_figures.py` and run the script again; do not edit the content between the comments by hand.

When a document changes, change the Chinese file and the `.en` file of the same name together. Run the commands and example code in a document on your machine before you submit it.

## Submitting

Contributions are released under the [MIT license](LICENSE). State the reason in the commit message. Do not commit secrets, access tokens, `runs/`, or real business data.

Record behavior changes in the Unreleased section of `CHANGELOG.md`. When a document changes, change the Chinese file and the `.en` file of the same name together. Run the commands and example code in a document on your machine before you submit it.
