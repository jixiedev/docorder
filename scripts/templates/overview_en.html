Python library · stage runner

Run the same transforms over a batch of directories, stage by stage

Each object is a directory (an entity). Operators form a DAG. One stage finishes the whole batch before the next starts. Progress lives on disk, so the same epoch can resume after a stop.

In short

Docorder is for long, interruptible batch work over many similar objects—not for one-off scripts that must start over after every failure.

1 Entities on disk

Each directory holds a data body and a tag.json. Results and upstream snapshots stay with the object.

2 Operators in a graph

Five types: source, map, reduce, fanout, apply. Homes live under DOCORDER_HOMES; the job picks the output path for a run.

3 Resume by epoch

The runner keeps matching upstreams, redoes changed ones, and deletes leftovers. Details in How a run works.

Core terms

Enough to read the rest of the docs. Full definitions: chapter 2 and the glossary.

  • EntityOne directory: body + tag; the unit of work.
  • OperatorA reusable transform (home + props.json), not tied to one run’s path.
  • Epoch / stageOne named batch of results; one hop in the job graph.
  • Upstream snapshotWhat upstream this result came from—used to decide keep vs redo.
